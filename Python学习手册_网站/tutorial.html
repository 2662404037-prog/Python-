第 0 章 · 上手前必须知道的 5 件事

0.1 什么是"库"

打比方：Python 本体是一个基础工具箱（螺丝刀、锤子）。而"库"是别人造好的成品模块——你想做个柜子，不用从砍树开始，直接买一块现成的板子拼上去。

  • 标准库：Python 自带，装好就有（json、sqlite3、collections…），不用 pip install
  • 第三方库：别人写的，要自己装（requests、pandas、numpy…）

判断方法：写 import xxx 如果报 ModuleNotFoundError —— 说明这是第三方库，需要装。

0.2 装库：就一条命令

text
pip install 库名

常用变体：

text
pip install requests              # 装
pip install requests==2.32.3      # 装指定版本
pip install -U requests           # 升级
pip uninstall requests            # 卸载
pip list                          # 看装了什么

国内下载慢？加个镜像源：

text
pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple

0.3 为什么要用"虚拟环境"

打比方：虚拟环境就是给每个项目一个独立的调料柜。A 项目要 numpy 1.x，B 项目要 2.x，装在同一个锅里就会打架。

text
python -m venv .venv                 # 创建（在项目文件夹里执行一次）
.venv\Scripts\activate               # Windows 激活
source .venv/bin/activate            # macOS / Linux
deactivate                           # 退出

激活后命令行前面会出现 (.venv) 字样，说明你在自己的调料柜里了。

小白也能记住的一句：每开一个新项目，先建虚拟环境，再 pip install。

0.4 代码写在哪里跑

方式 适合 怎么用
VS Code 写正式代码（推荐） 装 Python 扩展，Ctrl+F5 运行
IDLE 刚入门随便试试 开始菜单搜 IDLE，File → New File
Jupyter Notebook 边写边看结果、做数据分析 pip install jupyter 后 jupyter notebook

💡 给初学者的小建议：从 IDLE 或 VS Code 起步，等做数据分析时再上 Jupyter。

0.5 报错了怎么看（这一步学会，能省一半时间）

Python 的报错信息从下往上看：

text
Traceback (most recent call last):
  File "test.py", line 3, in <module>
    print(1 / 0)
ZeroDivisionError: division by zero
  • 最后一行 = 错在哪类（ZeroDivisionError = 除以 0）
  • 倒数第二行 = 错在哪一行（line 3）
  • 中间的 File "xxx", line N = 出错的位置

新手最常遇到的 5 个报错：

报错 中文意思 怎么改
ModuleNotFoundError: No module named 'requests' 没装这个库 pip install requests
NameError: name 'df' is not defined 变量名写错 / 还没定义就用 检查拼写、检查顺序
TypeError: can only concatenate str (not "int") to str 字符串和数字相加了 用 str(数字) 转一下
IndentationError 缩进错了 统一用 4 个空格
KeyError: 'xxx' 字典里没有这个键 用 d.get("xxx", 默认值)

第 1 章 · 数据处理：让数字自己算

这一章解决三件事：算得快（numpy）、算得省事（pandas）、看得懂（matplotlib）。

1.1 numpy —— 让数字"整体"运算

它是什么：Python 的列表做乘法是"重复"，而 numpy 的数组做乘法是"每个元素都乘"。

text
pip install numpy

第一个例子：

python
import numpy as np

a = np.array([1, 2, 3, 4])
print("整体乘 2:", a * 2)
print("均值/最大:", a.mean(), a.max())

m = np.arange(6).reshape(2, 3)      # 0~5 排成 2 行 3 列
print("2x3 矩阵:")
print(m)
print("每列求和:", m.sum(axis=0))

运行结果（我实测的）：

text
整体乘 2: [2 4 6 8]
均值/最大: 2.5 4
2x3 矩阵:
[[0 1 2]
 [3 4 5]]
每列求和: [3 5 7]

逐行在干嘛：

  • np.array([1,2,3,4]) —— 把普通列表变成"数组"，这是 numpy 的基本单位
  • a * 2 —— 每个元素都乘 2（普通列表会变成重复 8 个元素，这就是区别）
  • a.mean() / a.max() —— 直接求平均、求最大，不用自己写循环
  • np.arange(6) —— 生成 0,1,2,3,4,5；.reshape(2,3) 把它排成 2 行 3 列
  • m.sum(axis=0) —— 沿"第 0 轴"（竖着）求和 = 每列的和

改一改试试：

  1. 把 a * 2 改成 a + 100、a ** 2（平方），看看结果
  2. 把 .reshape(2,3) 改成 .reshape(3,2)，看看矩阵变成什么样
  3. 把 axis=0 改成 axis=1（每行求和），对比一下
一句话记住：numpy 快，是因为它不写 for 循环。

1.2 pandas —— Python 里的"Excel"

它是什么：把数据变成带表头的表格，然后能像在 Excel 里一样筛选、排序、分组、统计——只是用代码，而且能处理几十万行。

text
pip install pandas openpyxl

第一个例子：

python
import pandas as pd

df = pd.DataFrame({
    "姓名": ["张三", "李四", "王五"],
    "分数": [686, 655, 700],
    "城市": ["杭州", "武汉", "北京"],
})
print(df)
print("平均分:", round(df["分数"].mean(), 1))
print("筛选 >=680:")
print(df[df["分数"] >= 680][["姓名", "分数"]])
print("按城市分组均值:", df.groupby("城市")["分数"].mean().to_dict())

运行结果：

text

0  张三  686  杭州
1  李四  655  武汉
2  王五  700  北京
平均分: 680.3
筛选 >=680:
   姓名   分数
0  张三  686
2  王五  700
按城市分组均值: {'北京': 700.0, '杭州': 686.0, '武汉': 655.0}

逐行在干嘛：

  • pd.DataFrame({...}) —— 把字典变成表格；字典的键变成表头
  • df["分数"].mean() —— 选出"分数"这一列求平均（round(x, 1) 是保留 1 位小数）
  • df[df["分数"] >= 680] —— 按条件筛选行（这行是 pandas 的灵魂，先记住形状）
  • [["姓名","分数"]] —— 只保留这两列
  • groupby("城市") —— 按城市分组，"每个城市的平均分是多少"

改一改试试：

  1. 加一行 ("赵六", 720, "上海")，重新跑
  2. 改成筛选"分数在 660~700 之间"：df[(df["分数"] >= 660) & (df["分数"] <= 700)]
  3. 把它存成 Excel：df.to_excel("成绩.xlsx", index=False)（index=False 是去掉左边那列编号）
一句话记住：pandas 是"用代码操作 Excel"，筛选用 df[条件]，统计用 .mean() / .value_counts() / .groupby()。

第 2 章 · 算法与数据结构：让程序变快

这一章有个反常识的重点：最好用的"算法库"其实是 Python 自带的，不用装。
很多人不知道标准库里已经有好东西，白白手写几十行。

2.1 三件套：Counter / deque / defaultdict

它们是什么（都来自标准库 collections）：

  • Counter = 自动计数器。给它一堆东西，它告诉你"每个出现了几次"
  • deque = 双端队列。两头都能快速进出（比 list 当队列快）
  • defaultdict = 会"自动初始化"的字典，省掉写 if k in d
python
from collections import Counter, deque, defaultdict

# ① Counter：统计出现次数
words = "苹果 香蕉 苹果 橘子 苹果 香蕉".split()
c = Counter(words)
print(c)
print(c.most_common(2))

# ② deque：两头进出
q = deque(["乙", "丙"])
q.appendleft("甲")
q.append("丁")
print(list(q), "-> 左边弹出:", q.popleft())

# ③ defaultdict：自动建列表
groups = defaultdict(list)
for name, cls in [("张三", "一班"), ("李四", "二班"), ("王五", "一班")]:
    groups[cls].append(name)
print(dict(groups))

运行结果：

text
Counter({'苹果': 3, '香蕉': 2, '橘子': 1})
[('苹果', 3), ('香蕉', 2)]
['甲', '乙', '丙', '丁'] -> 左边弹出: 甲
{'一班': ['张三', '王五'], '二班': ['李四']}

逐行在干嘛：

  • Counter(words) —— 一行完成"统计词频"，比手写字典计数循环省事
  • .most_common(2) —— 出现最多的前 2 个，返回列表 %[(值, 次数)]%
  • q.appendleft("甲") —— 从左边塞进去；popleft() 从左边取出来 → 这就是"队列/双端队列"
  • defaultdict(list) —— 访问不存在的键时自动创建空列表，所以 .append 不会报错

改一改试试：

  1. 把 Counter 换成统计一句话里每个字出现的次数
  2. 用 Counter 找出一段文字里出现最多的前 3 个词
  3. 用 defaultdict(int) 做"按班级统计人数"
一句话记住：要计数用 Counter，要队列用 deque，要分组用 defaultdict。

2.2 heapq 和 bisect —— 排序相关的两个神器

它们是什么：

  • heapq = 最小堆。永远能 O(1) 拿出最小值，适合"每次都取最小的"
  • bisect = 二分查找。在有序列表里查位置/插入，O(log n)
python
import heapq, bisect

# heapq：最小值总是在最前面
nums = [5, 1, 8, 3]
heapq.heapify(nums)
print("堆里:", nums, " 最小值:", nums[0])
print("弹出:", heapq.heappop(nums), "剩下:", nums)
print("最大的两个:", heapq.nlargest(2, [10, 3, 99, 42]))

# bisect：有序列表里找位置
scores = [60, 70, 80, 90]
print("85 该插在位置:", bisect.bisect_left(scores, 85))
bisect.insort(scores, 85)          # 插进去还保持有序
print("插入后:", scores)

运行结果：

弹出: 1 剩下: [3, 5, 8]
最大的两个: [99, 42]
85 该插在位置: 3
插入后: [60, 70, 80, 85, 90]

逐行在干嘛：

  • heapify(nums) —— 把普通列表整理成"堆"（注意打印出来是 [1,3,8,5]，不是排好序的，但最小值一定在 [0]）
  • heappop() —— 弹出最小值，并自动把剩下的重新整理成堆
  • nlargest(2, ...) —— 取最大的 2 个（比先排序再切取更省资源）
  • bisect_left(scores, 85) —— "85 应该插在下标 3 的位置"（因为 80 < 85 < 90）
  • insort = insert + sort：插进去还保持有序

2.4 functools.lru_cache —— 一行让递归快 1000 倍

它是什么：记忆化。函数算过的参数就存起来，下次同样参数直接返回结果，不再重算。

python
from functools import lru_cache

calls = 0
@lru_cache(maxsize=None)          # ★ 就是这一行
def fib(n):
    global calls
    calls += 1
    return n if n < 2 else fib(n-1) + fib(n-2)

print("fib(30) =", fib(30))
print("实际计算次数:", calls)

运行结果：

text
fib(30) = 832040
实际计算次数: 31

为什么这么神奇：不用 lru_cache 时，算 fib(30) 要重复计算几百万次；用了以后，因为每个 fib(k) 只算一次，所以总共只算了 31 次（k=0~30）。

改一改试试：

  1. 把 @lru_cache 那行注释掉，把 30 改成 25，看看要跑多久（会明显变慢）
  2. 用 lru_cache 加速"爬楼梯"问题（每次走 1 或 2 阶，共有几种走法）
一句话记住：递归慢，先想 lru_cache。

  1. 链接是相对路径 —— 页面上是 catalogue/xxx.html，存进数据库没法用。

from urllib.parse import urljoin

HEADERS = {"User-Agent": "StudyBot/1.0 (learning only)"}
conn = sqlite3.connect("books.db")
conn.execute("CREATE TABLE IF NOT EXISTS books(url TEXT PRIMARY KEY, title TEXT, price REAL)")

url, page = BASE, 0
while url and page < 3:                    # 抓 3 页就停（别给人家添麻烦）
    page += 1
    r = requests.get(url, headers=HEADERS, timeout=15)
    if r.status_code != 200:
        print("抓取失败:", r.status_code); break

    soup = BeautifulSoup(r.text, "lxml")
    for card in soup.select("article.product_pod"):
        a = card.select_one("h3 a")
        p = card.select_one("p.price_color")
        if not (a and p):
            continue
        price = float("".join(c for c in p.get_text() if c.isdigit() or c == "."))
        conn.execute("INSERT OR IGNORE INTO books VALUES (?, ?, ?)",
                     (urljoin(url, a["href"]), a["title"], price))
    conn.commit()
    print("第", page, "页完成")

    nxt = soup.select_one("li.next a")
    url = urljoin(url, nxt["href"]) if nxt else None
    time.sleep(1)                          # ★ 限速：每页间隔 1 秒

print("总共:", conn.execute("SELECT COUNT(*) FROM books").fetchone()[0], "本")
for row in conn.execute("SELECT title, price FROM books ORDER BY price DESC LIMIT 3"):
    print(row)
conn.close()

4.1 socket —— 网络编程的"地基"

它是什么：socket 是操作系统留给你程序的网络接口。你听到的一切网络词（TCP、连接、端口）最后都落到它身上。理解它，才知道 requests 和浏览器在背后干了什么。

第一个例子：检查本机某个端口通不通（不会打扰任何人）

python
import socket

def check(host, port, timeout=1):
    """能连上返回 True，连不上返回 False"""
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.settimeout(timeout)
        return s.connect_ex((host, port)) == 0

print("本机 1 端口开放吗:", check("127.0.0.1", 1))
print("本机 65500 端口开放吗:", check("127.0.0.1", 65500))
print("本机 IP:", socket.gethostbyname(socket.gethostname()))

运行结果：

text
本机 1 端口开放吗: False
本机 65500 端口开放吗: False
本机 IP: 10.120.0.140

逐行在干嘛：

  • socket.socket(AF_INET, SOCK_STREAM) —— 建一个 TCP 类型的网络插座（AF_INET = IPv4）
  • settimeout(1) —— 最多等 1 秒，不然可能卡很久
  • connect_ex((host, port)) —— 尝试连接，返回 0 表示成功，其它数字表示失败原因
  • ` with s` —— 用完自动关闭（好习惯）
💡 127.0.0.1 是什么意思：它就是"本机自己"。练习时永远先拿它当目标。

4.2 hashlib / hmac —— "指纹"，不能还原

它是什么：哈希（摘要） 就是把任意内容压成一串固定长度的"指纹"。同一个内容 → 永远同一个指纹；内容改一个字 → 指纹完全不同。

关键：哈希是单向的，不能从指纹反推出原文。（加密才可逆，别搞混）

python
import hashlib, hmac

print("sha256:", hashlib.sha256(b"hello").hexdigest())

sig = hmac.new(b"key", b"data", hashlib.sha256).hexdigest()
print("hmac:", sig)
print("内容一样结果就一样:", hmac.new(b"key", b"data", hashlib.sha256).hexdigest() == sig)

运行结果：

text
sha256: 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
hmac: 5031fe3d989c6d1537a013fa6e739da2f6991c2a3dab0b0e5a2c1c9c36d3bb3e
内容一样结果就一样: True

它用来干什么：

  • 校验文件有没有被改过（下载大文件后比对 sha256）
  • 接口签名（hmac：带一把密钥，防止别人伪造请求）
  • 去重（内容一样 → 指纹一样）

注意：b"hello" 前面的 b 表示字节，哈希只能处理字节，字符串要先 .encode()。

4.4 bcrypt —— 存密码的"正确姿势"

它是什么：专门用来存用户密码的哈希算法。它的特点是故意很慢，并且自动加盐（同一密码两次结果也不同），让暴力破解变得几乎不可能。

text
pip install bcrypt
python

# 注册时：把密码变成哈希，存进数据库

hashed = bcrypt.hashpw(password, bcrypt.gensalt())
print("存进数据库的哈希:", hashed[:29], "...")   # 形如 b'$2b$12$...'

# 登录时：用用户输入去校验（不用解密，哈希本来就不可逆）
print("密码对不对:", bcrypt.checkpw(b"user-password-123", hashed))   # True
print("密码对不对:", bcrypt.checkpw(b"wrong-password", hashed))      # False

为什么不能用 md5 存密码：md5 太快，一秒能试几亿次；bcrypt 一次要几十毫秒，暴力破解直接不现实。再加"加盐"，同一密码在不同用户那里哈希也不同。

4.5 cryptography —— 真正意义上的"加密"

它是什么：和哈希不同，加密是可逆的——有钥匙就能还原。它用来保护"必须还原"的数据，比如配置文件里的密码、通信内容。

text
pip install cryptography
python

token = f.encrypt(b"我的秘密")
print("密文:", token[:40], "...")
print("解密:", f.decrypt(token))     # 拿到钥匙就能还原
🔑 钥匙丢了，数据就永远打不开了（这不是 bug，是特性）。
🔐 引申一句：API Key、数据库密码绝不要写死在代码里，用环境变量或 python-dotenv 读取，并且把配置文件加进 .gitignore。

6.1 FastAPI —— 10 行写出一个接口

它是什么：API 就是"别人可以调用你的函数"。比如你写了个"分析分数"的函数，用 FastAPI 包一层，别人就能通过网址调用它。

它最大的优点：你只要写清楚类型，它自动帮你校验参数并生成一份能点击测试的文档。

text
pip install "fastapi[standard]"

新建文件 main.py：

python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI(title="我的第一个接口")

class Student(BaseModel):                     # 定义"请求要长什么样"
    姓名: str = Field(min_length=1)
    高考分数: int = Field(ge=0, le=750)       # 分数必须在 0~750 之间

@app.get("/")                                 # 访问根路径时返回的
def home():
    return {"message": "服务已启动"}

@app.post("/analyze")                         # POST /analyze 时执行
def analyze(stu: Student):
    if stu.高考分数 >= 700:
        level = "顶尖"
    elif stu.高考分数 >= 660:
        level = "优秀"
    else:
        level = "普通"
    return {"姓名": stu.姓名, "等级": level}

http://127.0.0.1:8000/docs 自动生成的接口文档，可以点"Try it out"直接测试！

逐行在干嘛：

  • class Student(BaseModel) —— 用一个类描述"请求体应该有哪些字段"，字段名和类型都写清楚
  • Field(min_length=1) / Field(ge=0, le=750) —— 直接在这里加校验规则
  • @app.post("/analyze") —— 声明"当别人往 /analyze 发 POST 请求时，执行下面的函数"

from datetime import datetime

data = [("周一", 8), ("周二", 7.5), ("周三", 9), ("周四", 8.5), ("周五", 7)]

doc = Document()

t.rows[0].cells[0].text = "日期"; t.rows[0].cells[1].text = "工时"
for d, h in data:
