你会看到这样的结构：

html
<article class="product_pod">
    <h3><a href="catalogue/a-light-in-the-attic_1000/index.html" title="A Light in the Attic">A Light in the Attic</a></h3>
    <p class="star-rating Three"></p>            <!-- 星级藏在 class 里！ -->

这一步要产出三个结论（写在纸上或注释里）：

  1. 一页有多少条 → 20 条，外层容器是 article.product_pod
  2. 要抓哪些字段、分别在哪 → 标题在 h3 a、价格在 p.price_color、库存 p.instock、星级在 p.star-rating 的 class 里
  3. 怎么翻页 → 页面底部有 <li class="next"><a href="page-2.html">next</a></li>
💡 新手最大的误区：不看页面结构就开始写 find，写十行删九行。
先看清结构，代码只有几行。

3. 第 ② 步：发请求（requests）

最小可用版本：

python
import requests

url = "https://books.toscrape.com/catalogue/page-1.html"
resp = requests.get(url, timeout=15)
print(resp.status_code)      # 200
print(resp.text[:300])       # 看前 300 个字符

但能跑 ≠ 专业。 一个"不容易出事"的请求必须做这 4 件事：

python
HEADERS = {"User-Agent": "StudyBot/1.0 (learning crawler; for practice site only)"}

resp = requests.get(url, headers=HEADERS, timeout=15)

if resp.status_code == 200:
    resp.encoding = resp.apparent_encoding      # ① 防中文乱码
    html = resp.text
必做 为什么
timeout=15 没超时，遇到卡住的连接程序会永久挂住
headers=... 默认 UA 是 python-requests/2.x，很多站点会直接拒绝；写明身份也更礼貌
检查 status_code 404/403 时 resp.text 是错误页，直接解析会得到空结果，很难排查
apparent_encoding 中文站常是 GBK，用默认编码会得到一堆乱码

常见状态码

  • 200 正常
  • 403 被拒绝（多半是 UA 或 IP 的问题）
  • 404 页面不存在（检查 URL 拼写）
  • 429 请求太频繁（必须降速，这是服务器在警告你）
  • 5xx 服务器出错（可以稍后重试）

4. 第 ③ 步：解析 HTML（BeautifulSoup）

python
from bs4 import BeautifulSoup
from urllib.parse import urljoin

RATING_MAP = {"One": 1, "Two": 2, "Three": 3, "Four": 4, "Five": 5}

def parse_page(html, page_url):
    soup = BeautifulSoup(html, "lxml")        # lxml 比 html.parser 快
    books = []

    for card in soup.select("article.product_pod"):        # ① 遍历每一本书
        title_tag = card.select_one("h3 a")
        price_tag = card.select_one("p.price_color")
        stock_tag = card.select_one("p.instock.availability")
        rating_tag = card.select_one("p.star-rating")

        if not (title_tag and price_tag):                  # ② 结构不对就跳过
            continue

        raw_price = price_tag.get_text(strip=True)         # "£51.77"
        price = float("".join(c for c in raw_price
                              if c.isdigit() or c == "."))  # → 51.77

        stars = 0                                          # ③ class 里找星级
        if rating_tag:
            for cls in rating_tag.get("class", []):
                if cls in RATING_MAP:
                    stars = RATING_MAP[cls]

        books.append({
            "title": title_tag.get("title") or title_tag.get_text(strip=True),
            "price": price,
            "rating": stars,
            "in_stock": 1 if stock_tag and "In stock" in stock_tag.get_text() else 0,
            "url": urljoin(page_url, title_tag["href"]),   # ④ 相对链接转绝对
        })
    return books

逐段解释

① soup.select("article.product_pod")

CSS 选择器，article.product_pod 意思是"标签是 article 且 class 里有 product_pod"。返回列表，所以能 for 遍历。select_one 只取第一个。

② 为什么要 if not (...) 判断

网页随时可能改版、某条数据可能缺字段。直接 title_tag.get_text() 会在数据缺失时抛 AttributeError 让整个程序崩掉，一条脏数据毁掉一整轮抓取，很不划算。习惯是"缺了就跳过，并记日志"。

③ 星级为什么这么麻烦

<p class="star-rating Three"> —— 星级不是文字，而是写在 class 名字里（One~Five）。

所以取 tag["class"]（返回列表如 ["star-rating", "Three"]），逐个比对映射表。

这类"数据藏在属性里"的情况非常常见，比如 <span data-score="4.5">。

④ urljoin 一定要会

页面上写的是相对路径 catalogue/xxx/index.html，直接存进数据库没法用。

urljoin("https://books.toscrape.com/catalogue/page-1.html", "catalogue/xxx/index.html") 会正确拼成完整 URL。

新手常犯的错：手动写 BASE + href，结果多一个斜杠、少一层目录，全 404。

CSS 选择器速查

写法 含义 例子
tag 标签名 select("a")
.cls class select(".price_color")
#id id select("#main")
a b 后代（任意层级） select("div.product_price p")
a > b 直接子元素 select("ul > li")
[attr] 有某属性 select("a[href]")
[attr=值] 属性等于 select("a[title='X']")

取内容的三兄弟：tag.get_text(strip=True) 取纯文本、tag["href"] 取属性、tag.get("title") 取属性（没有返回 None 而不报错）。

5. 第 ④ 步：翻页（while + "下一页"按钮）

python
def next_page_url(html, page_url):
    soup = BeautifulSoup(html, "lxml")
    nxt = soup.select_one("li.next a")
    return urljoin(page_url, nxt["href"]) if nxt else None   # 没有就返回 None

url, page = START_URL, 0
while url and page < max_pages:          # ← 两个退出条件，缺一不可
    page += 1
    html = fetch(url)
    rows = parse_page(html, url)
    save_books(conn, rows)
    time.sleep(1.0)                      # ★ 限速
    url = next_page_url(html, url)       # 更新为下一页

三个坑

  1. 最后一页没有"next"按钮 → select_one 返回 None → nxt["href"] 会 TypeError。

正确做法：用 if nxt else None 让 while 自然结束。

  1. 死循环：如果"下一页"的链接永远指向自己（有的站分页写错），while url 会转到天荒地老。

所以一定要加 page < max_pages 这个上限兜底。

  1. 不给服务器喘气：一秒钟发几十个请求 = 事实上的 DoS，会被封 IP，也很不道德。

本项目默认每页停 1 秒（time.sleep(1.0)）。

翻页的另外两种常见形态
- URL 有规律：?page=1,2,3... → 直接 for i in range(1, 51) 拼 URL，不需要解析"下一页"
- 滚不到底：瀑布流、无限滚动 → 用 playwright 滚动加载，或直接找它背后的 JSON 接口（DevTools 的 Network 面板筛 Fetch/XHR）

6. 第 ⑤ 步：存起来（SQLite）

为什么不直接存 CSV？

CSV SQLite
追加写入 要读出来再写回去，容易写乱 INSERT 一行即可
去重 自己想办法 主键 UNIQUE + ON CONFLICT 自动搞定
查询 全读进内存 SELECT ... WHERE 直接查
中途崩了 文件可能写坏 有事务保护
依赖 无 无（标准库自带）
python
import sqlite3

conn = sqlite3.connect("data/books.db")
conn.execute("""
    CREATE TABLE IF NOT EXISTS books(
        url        TEXT PRIMARY KEY,     -- ★ 用网址做主键，天然去重
        title      TEXT NOT NULL,
        price      REAL,
        rating     INTEGER,
        in_stock   INTEGER,
        crawled_at TEXT
    )""")
conn.commit()

rows = [(r["url"], r["title"], r["price"], r["rating"], r["in_stock"], now) for r in data]
conn.executemany("""
    INSERT INTO books(url, title, price, rating, in_stock, crawled_at)
    VALUES (?, ?, ?, ?, ?, ?)
    ON CONFLICT(url) DO UPDATE SET
        title=excluded.title, price=excluded.price,
        rating=excluded.rating, in_stock=excluded.in_stock,
        crawled_at=excluded.crawled_at
""", rows)
conn.commit()

三个要点

  1. url 当主键：同一个 URL 只会有一行。这样重复跑脚本也不会产生重复数据，这是爬虫最实用的技巧之一。
  2. INSERT ... ON CONFLICT DO UPDATE（UPSERT）：已存在就更新。想"已存在就跳过"用 INSERT OR IGNORE。
  3. 问号占位符：executemany 的第二个参数。永远不要用 f-string 拼 SQL，那是 SQL 注入的入口（虽然这里数据是自己抓的，但习惯要从第一天养成）。

11. 第 ⑩ 步：让它更健壮（这才是"能用的爬虫"）

11.1 失败自动重试（tenacity）

网络抖动、超时、偶发 5xx 都太常见了，不要一失败就退出：

python
from tenacity import retry, stop_after_attempt, wait_fixed, retry_if_exception_type

class RetryableError(Exception):
    """网络类错误，交给 tenacity 重试"""

@retry(stop=stop_after_attempt(3), wait=wait_fixed(2),
       retry=retry_if_exception_type(RetryableError), reraise=True)
def fetch(url):
    try:
        resp = requests.get(url, headers=HEADERS, timeout=15)
    except requests.RequestException as exc:
        raise RetryableError(str(exc)) from exc     # 可重试的错误
    if resp.status_code >= 500:
        raise RetryableError("HTTP %d" % resp.status_code)
    if resp.status_code != 200:
        raise RuntimeError("HTTP %d" % resp.status_code)   # 4xx 不重试
    return resp.text

关键设计：区分"值得重试"（超时、5xx）和"重试也没用"（404、403、解析失败）。全都重试只会浪费时间和被封。

11.4 断点续爬

因为 url 是主键 + UPSERT，直接重新跑就会自动"续爬"（已抓的更新，没抓的补上），不需要额外的断点文件。

想更省流量，可以只抓"还没抓过的 URL"：

python
done = {row[0] for row in conn.execute("SELECT url FROM books")}
if book["url"] in done:
    continue          # 跳过已抓过的

13. ⚠️ 合规红线（必读，比技术更重要）

爬虫在中国是有明确法律边界的，这几条必须记住：

✅ 可以做

  • 抓取公开的、不违反站点条款的数据
  • 遵守 robots.txt
  • 控制频率（本教程默认每页 1 秒）
  • 用站点的官方 API（有 API 就别爬）
  • 在专门的教学站点上练习（books.toscrape.com、quotes.toscrape.com、httpbin.org）

❌ 绝对不能做

  • 绕过登录 / 付费墙 / 验证码 去拿非公开数据
  • 抓取个人信息（手机号、身份证、住址、聊天记录）—— 可能触犯《个人信息保护法》《刑法》253 条之一
  • 高频请求打挂对方服务 —— 可能构成《刑法》285/286 条的"破坏计算机信息系统"
  • 抓来的数据转卖、公开传播
  • 用爬虫做刷单、抢票、水军等

一句话判断法：

如果你要爬的东西，"用浏览器正常点开、不登录、不付费就能看到"，并且你只少量、低频、不传播地用于学习——那基本安全。
其他情况，先查法律、先问授权。
